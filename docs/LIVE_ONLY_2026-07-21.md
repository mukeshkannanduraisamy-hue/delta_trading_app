# Engine converted to LIVE ONLY — 2026-07-21

Paper (simulated-fill) mode has been **removed from the code**. There is now exactly one execution path: real orders on the Delta **testnet demo book** via `POST /v2/orders`.

**Starting the engine places real orders. There is no dry run.**

No real money is reachable — every signed request is hardcoded to `TESTNET_BASE` in [delta_client.py](delta_trading_app/strategy/delta_client.py), and the production base is used only for public market data. The order flow is genuine; the money is not.

---

## What changed

| file | change |
|---|---|
| `strategy/config.py` | `EXECUTION_MODE` / `LIVE_DEMO` pinned to live; `EXEC_BASE` always testnet. A non-`live_demo` value in `.env` now prints a startup **warning** instead of being silently honoured. `PAPER_START_BALANCE` → `SESSION_EQUITY_BASE`. |
| `strategy/executor.py` | All `if config.LIVE_DEMO` branches removed — entries and exits always send orders. `self.balance` → `self.session_equity`. Module docstring rewritten. |
| `strategy/engine.py` | New `preflight()`; `start()` **refuses** without working credentials. `reconcile()` now runs unconditionally. |
| `main.py` | Shutdown flatten no longer mode-gated. `/api/strategy/start` returns `blocked_reason` when preflight refuses. |
| `static/js/strategies.js` | PAPER badge removed (it could never be true). Start button now confirms, echoing trade size + armed strategy count, and surfaces a refused start. |
| `.env` | `EXECUTION_MODE` documented as a label with no effect. |

## New safety behaviour

Removing paper mode removed a fallback, so two guards were added to replace it:

**1. Preflight on start.** Previously, missing credentials meant the engine quietly ran in paper mode. Now it would fire signals and fail every order while *looking* like it was trading. `Engine.preflight()` checks credentials against the exchange and refuses to start, journalling `start_refused`:

```
[engine] REFUSED TO START — DELTA_API_KEY / DELTA_API_SECRET are not set.
This engine places real testnet orders and has no simulated fallback.
```

An API *reachability* problem (as opposed to a credential rejection) is a warning, not a blocker — exits must still be able to run during an API wobble.

**2. Start confirmation.** One click now sends real orders, so the button confirms first and echoes back the size:

```
Arm the engine — LIVE ONLY.
Real orders will be placed on the Delta testnet demo book.
There is no paper mode and no dry run.

  size            : 1 contract(s) per trade
  strategies armed: 0
```

This catches an unintended `ENGINE_CONTRACTS` before the first fill rather than after it — the previous config was `100`.

## `session_equity` is not a wallet

The old `balance` field was a virtual paper wallet. In a live-only engine that name is actively misleading, so it is now `session_equity`: a P&L line starting from a notional base, used only to plot "P&L since the engine started". The authoritative demo-account balance comes from `GET /api/account`, which reads the exchange. The UI label is now **"Session P&L"**. A `balance` alias remains in `stats()` for back-compat.

## What this does not change

The 90-day study ([RETUNE_STUDY_2026-07-21.md](RETUNE_STUDY_2026-07-21.md)) stands: **0 of 274 parameter combinations showed positive expectancy**, direction is a coin flip under a shuffle test, and Delta's fees alone cost 2.22 R per trade at 1m.

Running this engine is an **execution test** — it validates the audit fixes (`reduce_only`, idempotent recovery, orphan reconciliation, the expiry floor) against a real venue. It is not expected to make money, and `ENGINE_CONTRACTS=1` should stay at 1 until there is a reason for it not to be.

`ENGINE_AUTOSTART=false` remains the last line of defence: nothing trades until someone clicks Start and confirms.
